解决 Windows 网络配置问题

解压整个文件夹后使用（若通过 Git 克隆源码仓库且 scripts\ 下尚未包含 .exe，可先运行 scripts\Build-Tools.ps1 从源码编译，或从 GitHub Releases 下载预编译 .exe 放入 scripts\）。能在 Windows 本机执行工具的 Codex、GPT 或 Gemini：让它打开此目录并先读 SKILL.md。使用网页版时，把 SKILL.md 和当前分支的参考文档作为文字提供，检查器由你在本机运行。无需提供自己的服务器 IP、域名或节点分享链接。

可直接发送给 AI
“请用这份技能，在我这台 Windows 电脑定位实际失败环节并修复。我的症状是 ____，原网络和代理模式是 ____。请先做只读对照，涉及持久写入时说明具体影响与回滚方法。若我已安装 Codex，主动检查重连和工作空间加载问题；若单独指定范围，按该范围执行。最后从普通图标验证浏览器和真实聊天。如果更改了系统代理，请分别测试只关系统代理、完全退出客户端、重新开启；如果配置了登录启动，再记下重新登录后的结果。请分开报告已恢复和仍待验证的部分。”

系统代理：普通桌面环境下双击 scripts\Check-WindowsProxy.exe。它只读检查；本地端口不同可用 --port 参数。输出中的 loopback 指本机。
每次退出代理都要手动修复、正在使用 Windows 宽带拨号时，请 AI 阅读 references\ppp-sync.md，先核实开关和端口是否同步。普通 Wi-Fi、路由器拨号的电脑从 SKILL.md 选择对应分支。
Codex：打开并登录 Codex，双击 scripts\Repair-CodexReconnect.exe。它会做握手对照，只有临时开关有效且你同意时才备份并保存一项用户配置。若已有相应授权，本机 AI 可使用 --apply --no-pause；仅诊断使用 --check --no-pause。没有安装 Codex 可跳过。
限制执行程序的设备，请使用管理员允许的工具完成文档中的只读检查。回传时仅复制状态和耗时，遮盖截图里的用户名、私人路径或实际域名。请勿上传完整配置、注册表备份、网络日志或私有节点信息。
