# Windows 当前用户代理和开关状态

## 读对设置层

在平时用浏览器的 Windows 账号、原网络运行 `scripts/Check-WindowsProxy.exe`（若本地未预置，可从 Releases 下载或运行 [Build-Tools.ps1](../scripts/Build-Tools.ps1) 从[源码](../scripts/Check-WindowsProxy.cs)编译）。双击默认检查 `10808`。客户端显示其他端口时，用下方命令指定实际端口。退出码 0 表示检查执行完成，输出仍可能报告 `OFF mismatch` 等故障；按实际选路和普通浏览器的结果验收。在解压后的技能根目录打开 PowerShell，可运行以下两行。只读检查，不输出完整 PAC、例外列表或代理凭据。如果组织限制运行程序，使用获准的系统工具或联系管理员，记录可验证的范围。

```powershell
$port = [int](Read-Host '客户端显示的本地代理端口')
.\scripts\Check-WindowsProxy.exe --port $port --no-pause
```

- **监听与接口**：看实际端口，区分已连接的 PPP 与当前确实被选中的名称。多个 PPP 时按编号及 active-name-match 识别；`--dialup "名称"` 查询的非活动条目仅供复盘。
- **已保存配置**：比较 WinINet 的 LAN/default、活动 PPP、正确名和候选名记录的手动启用位与端点。端点仍有文字时，手动启用位也可能已关闭。
- **应用取值**：WinHttpGetIEProxyConfigForCurrentUser 取当前用户活动连接的代理。再看具体网址的系统选择、PAC、绕过规则和策略作用域。HKCU 的单个 ProxyEnable、机器级 WinHTTP 默认代理、普通网页上的一条超时，均不足以说明整条选路。程序以两个公共站点做样本；对现场其他目标在本机用同一系统代理查询或浏览器网络诊断复核。[微软接口说明](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpgetieproxyconfigforcurrentuser)
- **只有浏览器异常**：若系统查询正确而原浏览器仍失败，检查实际浏览器代理策略、扩展、绕过规则和第一个失败的资源域名。对比干净配置和明确指定代理的请求仅用于定位。

## 活动拨号记录错名

可用代理已在同一网络完成显式请求，但普通应用选 DIRECT 时，才考虑本分支。若没有活动 PPP、接口和普通应用均正常，保留现状。核对下面所有证据：

1. 当前用户、实际活动 RAS 名称及注册表视图已经确认。HKCU 下 `Software\Microsoft\Windows\CurrentVersion\Internet Settings\Connections` 缺少准确名称的值。
2. 找到唯一候选。已知个案中，准确名的 UTF-8 字节按 GBK（936）严格解码产生候选名，反向编码可逐字还原。出现替换字符、不可逆字符串、多候选或已有正名时，停止自动补值。
3. 核对候选与预期配置的 REG_BINARY 类型、已知布局的长度边界、手动启用位、现场端口和例外。已知案例中候选与默认值从偏移 8 起完全一致。未知布局应通过支持的 API/本机跟踪继续查证。flags 的位 0x2 表示手动代理，0x1 表示允许直连；本地地址绕过另查规则。

先备份受影响条目，在本机记录其原始存在性、类型、完整字节及校验值。首选客户端支持的每连接设置，刷新并让新普通进程查询。若确认错名且其他途径无效，经授权可做一次**可撤销的定向补值**：写前再查活动名、来源和目标，暂停会同时改代理的操作；只在缺失的准确名称下复制已核实的完整候选字节，保留旧值。两种视图可能共享数据，写一处后回读。可用受支持的 InternetSetOptionW 设置变更通知与刷新（39、37）；受限时由机主正常退出并重开浏览器，再读实际值。一次成功后立即做下列生命周期验收。

## 启用、退出、再启用

选择一个应走代理的网站和一个在本网络应能直连的网站。下面的 `--expect on/off` 提示用于预期使用本机**手动代理**的场景。PAC、合法上游代理或 TUN 模式使用默认观察，并按预期的逐网址路由和实际浏览结果判定。保存好进行中的任务，用同一用户的普通桌面环境逐阶段检查：

| 阶段 | 要看什么 |
|---|---|
| 客户端开启并启用系统代理 | `--expect on --port 实际端口`。监听存在，应代理的网址选择预期端点，普通浏览器加载完整网页。 |
| 只从托盘关闭系统代理，保持客户端运行 | `--expect off --port 实际端口`。本地端口可以继续监听。若关代理的基线为直连，普通浏览器应能访问可直连的网站。 |
| 按平时方式完全退出客户端 | 重新运行同一条 `--expect off` 检查。即使监听消失，浏览器也应维持原先的直连或既有上游。若用户通常在代理开启时直接退出，从开启状态单独复现这一动作。 |
| 再开启并选回同一节点 | 再用 `--expect on` 查询，普通浏览器恢复；必要时切换节点后再验。 |

当端口已停止监听，而正确名记录/当前接口仍启用这个端口，普通浏览器可能报 ERR_PROXY_CONNECTION_FAILED。对比每个阶段正确名与候选名的启用位、HKCU 开关及实际选路。若只有错名随客户端更新，注明“静态记录与开关脱钩”。比较期间每次重新启动检查器，避免沿用进程缓存。

**先恢复能直连，再谈长期方案。** 若正名值确由本轮创建，核实其所有权和内容后，仅撤销本轮新增项并通知、复查直连。若记录头发生变化，保留当前值并与备份比较；不要仅据尾部相同或某个偏移变化就自动删除。已有数据或并发修改需人工合并。不要删原候选、清空整棵键或用旧备份覆盖后续编辑。

如果没有 PPP，或残留代理原本就存在，优先重新打开同一客户端，用其“清除系统代理”功能后正常退出并复测。若仍残留，先确认原基线允许直连、机主有权管理该连接，并记录原设置。经授权只关闭实际生效连接上指向死端口的手动代理，保留 PAC、绕过和其他连接的设置。再从新普通进程访问直连网站，最后重开客户端验收代理恢复。

若拨号正名一补就通、每次退出又坏，进入[拨号连接的持续同步与回滚](ppp-sync.md)。优先验证当前客户端的每连接设置能否跟随开关。只在用户本来就希望改用 TUN 时，单独验证 DNS、路由、工作空间和退出后直连。
